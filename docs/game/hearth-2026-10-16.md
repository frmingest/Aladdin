# The Hearth (game mode E3) — 2026-10-16

Status: written and tested on branch `feature/hearth`, PR open, not merged, not deployed. Seen only in tests (no live check yet).

## What it is for
When the weather turns bad, the Hearth is the quiet room you sit in before you do anything. It shows, from stored data only, what moved, what held and what changed, and puts your own earlier words next to the numbers. It gives no score, no verdict and no advice.

## What it shows (`/fortress/hearth`, `GET /game/hearth`)
- **Open or shut.** Open when the newest stored frame's weather is gathering or besieged (`hearth_v1`: those two levels, 30 days look-back). Calm, unsurveyed or nothing stored: the door is shut, and the page says why.
- **Three shelves**, read off the Chronicle's own frame comparisons, so nothing is computed twice:
  - *Moved*: a tower changed size (`tower_resized`).
  - *Changed*: weather, wall, moat or thesis changed, or a tower joined or left.
  - *Held*: towers in the newest frame untouched by any recorded change in the look-back. With only one stored frame nothing can be called held, and the page says so.
- **Your own lines.** For each tower, the newest journal entry that has an invalidation line, verbatim with its date, beside the live value of each active tripwire set on that holding (read without writing). The line is free text and is never parsed into a metric.
- **Your winter order** and the **record** of the worst stored fall (from the E2 replay: fall, kroner, days under water, or why there is none).
- **Gaps.** Stretches with no stored frame are listed as "nothing recorded: the worker was off", never as calm or held.

## Decision: a new table, not the journal
The winter order lives in a new append-only table `winter_orders` (migration `x1f2a3b4c5d6`, additive; newest row is current; a blank row clears it). Journal entries are decisions about a holding and feed the temperament and calibration counts, so a book-wide note there would pollute them. `GET/PUT /game/winter-order`; demo mode reads empty and refuses the write. Winter Rehearsal now saves there too and keeps a browser copy as fallback; an order that exists only in the browser is sent up once.
