# Game-mode page identity audit (read-only, snapshot of origin/main)

Method: grep/read of `frontend/src` (paths below relative to it), docs, `.claude`. Nothing run in a browser; scores come from code only.
Score 0-3: count of (a) bespoke SVG/illustration, (b) game-specific components beyond `Card`/`PageHeader`/tables, (c) motion/feedback, (d) parchment/scroll/seal/raven/lamp primitives. 3 = three or four of them, 2 = two, 1 = one, 0 = none (vocabulary alone in the title/copy does not count).
Baseline every page gets for free in game mode: the "study" skin (`index.css:60-116`: Marcellus `.font-display`, gilded `.ui-card` edge, lozenge `.section-title`). That is why Circle/Council look like "normal mode in brown".

## 3. Root causes of plainness (quotes)

1. **Scope decision at the start: only the home scene is a "game screen".** `docs/game-mode-fortress-2026-10-01.md:144`: "D1 | 'Entire app changes' | **Fortress home scene + re-skinned existing pages** (not a full game copy of every page)". And :215-216: "every page changes feel, none is duplicated" - i.e. identity for non-scene pages was defined as colour tokens only.
2. **Noise audit made the plain pages the benchmark.** `game-mode-noise-audit-2026-10-07.md` §2.5: "Council (194 words) and Records (141 words) are close to the target already: one list, one lead sentence. **Use them as the benchmark for the game pages**". §3 "What I would not change": "the Council and Records pages". §2.6 point 3: "Fiction text next to facts ... they do not need to come before the answer on a page the person opens to decide." §7 "Not done: ... Council, Records and Circle untouched". The sprint plan then praises them: "The rituals (Council, Records, Circle) are the best-scoped pages" (`game-mode-sprint-plan-v2:22-23`).
3. **"One idea once" / "repeat nothing" is the only design rule the reviewer agent has.** `.claude/agents/game-ux-designer.md`: "Use the Aladdin noise-audit approach ...: one idea once, state shown by shape not colour alone. Output a prioritised findings list (blocker/should/nit)". Skill `game-ux-onboarding-accessibility/SKILL.md:7`: "one primary focus per screen; secondary info on demand; repeat nothing (see noise audit)". Its description: "first-run onboarding, information hierarchy, noise, colour-blind-safe status, reduced motion, keyboard and mobile". Nothing asks "does this room feel like the game / reuse a game primitive / have a place in the painted world".
4. **Every other gate is a restriction, none is a requirement for identity.** `.claude/standards/game-ui-standards.md` (8 rules): truth, not-colour-alone, reduced motion, keyboard, perf budget ("no animated SVG filters; <= a small fixed number of concurrent looping animations"), sound opt-in, no rewards, pure mapping fns. `game-feel-engineer.md`: "Animate only transform and opacity ... cap looping animations ... Juice must never change what a fact means"; it is invoked for effects, not for "this page has none". `game-designer.md` writes mechanics specs ("player verb, real fact, feedback, unknown handling") with no art/atmosphere field. `/game-review` (`.claude/commands/game-review.md`): designer "does it fit the principles?" -> ux -> feel -> playtest-qa (screenshots, console, frame rate) -> rules-auditor. playtest-qa reports what is seen vs "As built" claims; no one compares a room with the Fortress for look.
5. **The noise audit explicitly did not judge art.** Header: "Sound, motion and the painted scene are not text and were not judged", and its metric is visible-word count. Pages were scored by words and px height, so a page of 141 words of list text "won".
6. **Word budgets are enforced by tests, identity is not.** `ux-noise-audit-2026-10-06.md:76`: "A text budget as a guardrail ... fails if a page's default view exceeds a word budget (for example 150 words above the first fold, 400 total)"; `wordBudget.test.tsx` and G3 budget footer/tab strip; no equivalent test or checklist for "uses at least one game primitive".
7. **Rituals were specified as data features.** `game-mode-next-ideas-2026-10-03.md:55-57`: G17 "Agenda built from the existing rules", G18 "the journal as a library" (built as `Card`s, not a library), G19 "Circle of Competence map" (built as a bar, no map). Sprint-plan G35 "commissions ... drawn as map markers" and G37 "a short ceremony" were built as bar+glyph (`CartographerPage.tsx:43-70`, `RecordsPage.tsx:26`).

**Was per-page art ever scheduled?** Not for the rooms. Searching all game docs: art/illustration items are (i) Fortress scene (G7 art pass, `fortress-art-pass-2026-10-09`: options A, C, D; "Option B (a building shape per sector), E (marketplace and characters) and F (hand-painted layers) are not done"), (ii) Marketplace/Sal/Genie (their own sprints), (iii) G28 scroll reader and G39 sprite pilot ("One illustrated tower set ... for one wall tier"), (iv) team review D1-D8 (Plain lens, camera, style bible, tower portrait on holding page, spotlight, motion grammar, announcement hygiene, print) - all scene/accessibility, only D4 touches another page. Fortress doc :370 "Still procedural SVG ... sprites could still replace parts later", sprint plan :141 "Art is the long pole". No sprint item, in any doc, gives Council, Circle, Records, Map, Siege or Chronicle a room illustration, emblem or atmosphere. Siege and Chronicle got a strip/mini-scene only as their own feature.
